# fightai

2D MuJoCo ragdoll fighter trained with PPO. Fighter `a` (learned policy) fights
fighter `b` (a scripted shadow-boxing opponent) in a side-view physics sim, with
health/knockdown mechanics layered on top of raw contact physics.

## Setup

```bash
python -m venv .venv
.venv/bin/pip install mujoco gymnasium stable-baselines3 tensorboard
```

Requires a GPU-capable machine with a working OpenGL context for the viewer
(`watch.py` / `view.py`); training itself runs headless.

## Project layout

```
models/fighter2d.xml   two-fighter MJCF model (generated by build_model.py)
scripts/build_model.py generates fighter2d.xml
scripts/view.py         scripted shadow-boxing smoke test (no learning) + JOINTS/get_ctrl
scripts/env.py          Fighter2DEnv: the Gymnasium environment
scripts/train.py        PPO training entrypoint
scripts/watch.py        loads a checkpoint and renders it against the scripted opponent
scripts/dashboard.py    local web dashboard to monitor/trigger train & watch runs
checkpoints/            trained models, autosave checkpoints, tensorboard logs (gitignored)
```

## Running things

**Train:**
```bash
.venv/bin/python scripts/train.py --timesteps 5000000 --out my_run \
  [--resume-from checkpoints/some_checkpoint.zip] [--device cuda|cpu] [--n-envs 8]
```
Saves periodic checkpoints to `checkpoints/autosave/` (every `--save-freq` env
steps, default 5000) and a final model to `checkpoints/{out}_{timestamp}.zip`.
Safe to resume from any checkpoint after a crash or manual stop — training
survives being killed at any point except mid-write.

**Watch a trained policy:**
```bash
DISPLAY=:0 .venv/bin/python scripts/watch.py checkpoints/my_run_20260101_120000.zip
```

**Dashboard:** `.venv/bin/python scripts/dashboard.py` then open
`http://localhost:8787` — shows live training metrics (steps/reward/episode
length/fps), and buttons to start/stop training and the viewer without a
terminal.

## Environment design (`env.py`)

**Bodies:** each fighter is a 2D ragdoll (torso/head/arms/legs) constrained to
the XZ plane (`root_x`, `root_z` slide joints + `root_ry` hinge). 9 rotational
joints (head, shoulders, elbows, hips, knees) per fighter, all driven by
`motor` actuators.

**Movement:** `root_x` is *directly actuated* rather than learned from leg
coordination. Bipedal walking from scratch is a notoriously hard RL problem;
direct actuation lets the policy focus on the actual fighting decisions
(spacing, striking, guarding) instead of re-deriving locomotion. Fighter `b`
(scripted) uses a simple proportional controller on `root_x` to always walk
toward `a`, so the fight reliably closes distance regardless of what `a` does.

**Weapons/targets:** punches (forearms) and kicks (shins) are the only geoms
that register as "weapons"; targets are head/torso/leg. Damage is proportional
to MuJoCo contact normal force, capped per body part per step
(`MAX_STEP_DAMAGE`) so a single lucky impact can't insta-kill. Contact damage
only counts on a *new* contact (weapon-target pair not already touching last
step) — a persisting press (e.g. resting on a downed opponent) doesn't deal
repeat damage. This was a real bug: before this fix, once a fighter went down
the attacker could unload the per-step damage cap on every consecutive frame,
draining 100 HP in ~0.25s of sim time.

**Knockdowns are recoverable:** falling below `FALL_HEIGHT` isn't instant
death — a fighter has `DOWN_RECOVERY_STEPS` (~3s) to get back up before it
counts as a real knockout. Health hitting zero is always an immediate KO.

**Stagger:** leg damage builds a "stagger" meter that reduces actuator
authority and adds control noise, so losing your legs makes it genuinely
harder to keep standing rather than an arbitrary penalty.

## Reward shaping — what changed and why

The reward function went through several iterations, each driven by an
observed failure mode rather than guesswork:

1. **Root actuation + scripted approach** — walking from scratch never
   produced contact (starting distance exceeded max arm reach); direct
   `root_x` control fixed this immediately.
2. **Mutual-fall penalty** — trading a knockdown blow (both fighters fall,
   episode ends) was reward-neutral, so the agent learned to rush in for one
   big exchange instead of sparring. Added a penalty for simultaneous falls.
3. **Recoverable knockdowns** — falling was instant episode-end, capping
   fights at ~9% of the max possible duration. Made it recoverable with a
   timeout instead.
4. **Knockdown-entry penalty** — even with recovery, diving in for one big
   hit was still positive-EV (a capped hit is worth ~8–19 reward; getting up
   fast only cost ~1–3). Added a one-time punitive cost (`-30`) the instant a
   fighter goes down, on top of the recovery-window's per-step cost.
5. **Damage reward scaled down (`DAMAGE_REWARD_SCALE=0.35`)** — dense
   per-contact-force reward was still large enough to make "land one forceful
   hit" competitive with "actually cause a knockdown/KO." Rebalanced so
   outcome-based rewards (knockdown, real KO) dominate over raw contact
   force. Health accounting is unaffected — this only changes the RL signal.
6. **Posture penalty — added, then removed two rounds later.** Measured that
   the fighter spent ~24% of steps in a visibly crouched/off-balance posture
   even when not technically "down," and added a penalty for torso height
   below standing. Once the kick bonus and one-touch-one-hit fix (below)
   addressed the underlying causes — legs having no offensive use, and reward
   for staying near a downed opponent to keep farming hits — the posture
   penalty was removed again, since on its own it couldn't distinguish a
   sloppy stance from legitimate defensive crouching or a kick wind-up.
7. **Kick reward bonus (`KICK_REWARD_BONUS=2.0`)** — measured that kicks are
   physically slightly stronger than punches (higher leg mass + higher hip
   actuator gear) but that difference was invisible to the reward because
   `MAX_STEP_DAMAGE` caps every solid hit regardless of limb. The agent had
   no incentive to risk balance on a kick when punching was strictly safer.
   Added a reward-only (not health) multiplier for shin-landed damage.
8. **One-touch-one-hit** (see above) — fixed the "farm the downed opponent"
   exploit that the recovery-window mechanic alone didn't solve: a fighter
   could unload the per-step damage cap on every consecutive frame once the
   opponent was down, draining 100 HP in ~0.25s of sim time. Damage now only
   counts on a fresh weapon-target contact, not a persisting press.

**Diagnosis approach worth reusing:** most of these fixes came from writing a
short script to load a checkpoint, run N episodes, and measure something
concrete (contact force distribution, torso height histogram, knockdown
counts per episode, exact step index of each hit) rather than eyeballing the
viewer. The viewer is good for noticing *that* something looks wrong; these
scripts are what pin down *why*.

## Current state

Iterating checkpoint-to-checkpoint via `--resume-from` rather than retraining
from scratch each time — the fundamentals (approach, striking, balance) carry
over across reward tweaks, so only the specific behavior being corrected needs
to be relearned. Cumulative training so far is in the tens of millions of
timesteps across the full chain of checkpoints in `checkpoints/`.
